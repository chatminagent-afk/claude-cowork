## Akar masalah rekap v3 (kenapa selalu error) & solusinya

Di v3, status pekerjaan disimpan di sheet **terpisah** (`PekerjaanStatus`, append-log). Untuk membuat rekap harian, n8n harus **menggabungkan (join)** sheet `Pekerjaan` + `PekerjaanStatus` + `Komplain`. Saat salah satu sheet kosong, node Code di-skip dan rekap gagal / balas kosong.

**Solusi v4 (mengikuti pola v2 yang stabil):** status "terakhir" disimpan **langsung** di satu sheet ringkasan (`Tiket`). Rekap cukup membaca satu sheet — tidak ada join yang rapuh. Riwayat tetap tersimpan lengkap di `StatusLog`.

## Struktur Google Sheet v4 (7 tab)

Header **wajib di baris 1**, nama tab **persis** seperti di bawah (case-sensitive).

**1. `Tiket`** — satu baris per komplain & per batch pekerjaan. Inilah sumber rekap & dashboard.
`ID · Tipe · Tanggal · Proyek · Pelapor · Deskripsi · Lokasi · Kategori · Prioritas · Status · Total · Status_Workflow · Notify_Count · Updated_At · Timestamp_Submit`
- `Tipe` = `Komplain` atau `Pekerjaan`
- `Status` = status **terakhir** (Open/Proses/Selesai/Reject) — ini "status last updated" yang kamu minta
- `Status_Workflow` = lifecycle rekap: `pending` (baru) → `reported` (sudah masuk rekap) → `done` (selesai/reject, berhenti muncul)

**2. `RAB_Items`** — detail item pekerjaan (1 baris per item, untuk RAB & realisasi).
`Batch_ID · Tanggal · Proyek · Pekerja · Catatan · No_Item · Pekerjaan · Vol · Sat · Harga_Satuan · Total_Item · Total_Keseluruhan · Kategori_RAB · Timestamp_Submit`
- `Batch_ID` = sama dengan `Tiket.ID` pekerjaan
- `Kategori_RAB` = kategori untuk dashboard (Persiapan / Sipil & Partisi / Finishing / MEP / Furniture & Custom / dll)

**3. `StatusLog`** — log append setiap update status (pekerjaan & komplain).
`ID · Tipe · No_Item · Status · Catatan · Updated_By · Updated_At`
- Setiap update masuk ke sini **dan** memperbarui `Tiket.Status`. `No_Item` diisi untuk pekerjaan, kosong untuk komplain.
- `Status` memakai label seragam yang ramah filter: **Open / Proses / Selesai / Reject** (untuk pekerjaan, aplikasi menerjemahkan balik ke pending/inprogress/done secara otomatis). Jadi bisa langsung di-filter di Google Sheet.

**4. `RAB_Budget`** — budget rencana per proyek & kategori (diisi owner). Dipakai dashboard untuk "Budget vs Realisasi".
`Proyek · Kategori · Budget_Rencana`

**5. `Pekerja`** — `Nama · No_HP · Keterangan` (No_HP format 62xxx untuk notifikasi WA)

**6. `Project`** — `Project · Keterangan · Lokasi`

**7. `Recipients`** — penerima **rekap harian WA**. `Nama · No_WA · Aktif`
- Saat ini: **Ko Ronald** (628170703500) & **Hendi** (6281292780911), keduanya `Aktif = YA`.
- Tambah/ubah penerima cukup di sheet ini — tidak perlu edit n8n.

## Langkah Deploy

1. **Google Sheet**: buat 7 tab persis seperti `2026-06-13-TIM-Interior-v4.xlsx` (header baris 1). Bisa pakai spreadsheet yang sama dengan v3 (tinggal tambah tab baru) atau spreadsheet baru.

   - Kredensial Google Sheets benar (workflow memakai `Google Sheets account 2`).
   - `documentId` di node Google Sheets = ID spreadsheet kamu (default masih ID lama — ganti bila pakai spreadsheet baru).
   - **Aktifkan** workflow.
3. **Webform**: upload isi folder `webform v3 enhance/` (sudah `TEST_MODE = false`, endpoint `/v4/...`). Untuk uji tanpa server, set `TEST_MODE = true` di `index.html`.
4. Isi sheet `RAB_Budget` dengan budget rencana tiap proyek agar dashboard menampilkan perbandingan.

## Troubleshooting (kejadian saat deploy pertama)

**"Tidak ada hit ke n8n" saat simpan pekerjaan / kirim komplain (tapi dashboard masuk).**
Penyebab: webhook n8n default `httpMethod = GET`, jadi semua endpoint POST ditolak. **Sudah diperbaiki** — di workflow v4 ini `httpMethod` sudah di-set per endpoint: POST untuk `add-project, add-worker, submit-pekerjaan, update-status, submit-komplain, update-komplain-status`; GET untuk sisanya. Pastikan kamu meng-**import ulang** workflow `2026-06-13-...json` versi terbaru lalu **aktifkan** lagi.

**Dashboard error 429 "too many requests" (quota Google Sheets, limit 60 read/menit/user).**
Sudah dimitigasi: semua node Google Sheets kini **Retry On Fail** (5x, jeda 2,5 dtk) dan timeout dashboard di webform dinaikkan ke 30 dtk. Kalau masih sering kena karena dipakai banyak orang, ajukan kenaikan kuota di Google Cloud Console (project 673938546771) — gratis & cepat.
