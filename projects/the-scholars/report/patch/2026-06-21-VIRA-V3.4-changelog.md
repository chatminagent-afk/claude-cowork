## Root cause sebenarnya (koreksi diagnosis V3.3)
Diagnosis V3.3 ("device `D-GDNA8` tidak aktif") **keliru**. Bukti:
- Di V2, `Send GForm Link` justru memakai `D-GDNA8` dan link tetap keluar.
- Di V2 maupun V3.x, node `Query LINKS for GForm` & `Send GForm Link` **disabled**, jadi tidak pernah dieksekusi — device-nya tidak relevan.

Penyebab asli: **perubahan desain antara V2 dan V3, bukan device.**
- **V2:** AI menulis URL `forms.gle` langsung di pesannya. `Process All` hanya membuang tag `[SEND_GFORM]`, tapi URL tetap ada di `cleanOutput`, lalu dikirim `Reply Chat Kirimi`. Jalur node terpisah memang disabled (redundant) → tetap aman.
- **V3.3:** AI menulis tag bernama `[SEND_GFORM: Nama Link]` **tanpa URL**. `Process All` menghapus seluruh tag itu → `cleanOutput` jadi tanpa link. URL seharusnya dikirim jalur `Query LINKS for GForm → Pick GForm Link → IF GForm Resolved → Send GForm Link`, **tapi node-node kunci jalur itu disabled** → link hilang total (dibuang dari pesan utama + jalur khusus mati).

## Solusi V3.4 — sederhanakan (kembali ke pola V2, tapi data-driven)
Resolusi link dipindah ke dalam `Process All` (tidak ada node baru):
1. **`Process All` resolve link sendiri.** Saat tag `[SEND_GFORM: Nama Link]` terdeteksi, `Process All` membaca sheet LINKS via `$('Read LINKS Data')` (node ini sudah jalan di hulu, sebelum AI Agent), mencocokkan `Nama Link` (exact lalu fuzzy, hanya baris Status aktif), dan **menyisipkan URL asli ke `cleanOutput`**. Link ikut terkirim dalam 1 pesan oleh `Reply Chat Kirimi`.
   - Nama link kosong → default ke "GForm Pendaftaran Batch 5".
   - Link tidak ketemu → teks AI dipertahankan, ditulis warning di log (tidak mengirim link asal).
   - Guard anti-duplikat: kalau URL sudah ada di teks, tidak ditambah lagi.
2. **Matikan jalur GForm lama** (biar arsitektur ringkas, satu sumber kebenaran): `IF Send GForm`, `Query LINKS for GForm`, `Pick GForm Link`, `IF GForm Resolved`, `Send GForm Link`, `Send GForm Clarify` → semua `disabled`. Node tidak dihapus (disimpan utk referensi).
3. **Nyalakan `IF (Whitelist)`** → mode UAT aktif. Hanya nomor terdaftar yang diproses: 6285155202354, 6281510624599, 6596110395, 6589200455, 628176480658.
