## Masalah: chat "reset", bot tanya status (ortu/anak) berulang
Gejala dilaporkan pada chat `+62 813-7900-9567` dan terbukti pada sheet STATS live (row 124 & 125, user `62818815168` / lid `281453686477043`).

### Root cause
WhatsApp mengirim identitas `from` dalam dua bentuk untuk orang yang sama: kadang nomor HP (`62818815168`), kadang LID (`281453686477043@lid`). Saat datang sebagai `@lid`, `Chat Counter` men-set `user_phone = ''`.

Seluruh node STATS sudah konsisten memakai **`lid`** sebagai kunci stabil — KECUALI `Read User STATS`, yang mencari dengan **`No WA = user_phone`**. Saat `user_phone` kosong (@lid), `Read User STATS` tak menemukan baris user → `Cek_user_status` menganggap user baru → bot mengulang pertanyaan status, dan terbentuk baris STATS duplikat.

Bukti node lain sudah by lid:
- Read STATS (full, semua baris)
- Process Counter & Merge Data → cocokkan by `lid`
- Update to STATS → matchingColumns `["lid"]`
- Update User Status → matchingColumns `["lid"]`
- Re-Read STATS Debounce → lookup `lid`

## Perubahan (fix minimal, 1 node)
**`Read User STATS`** — lookup diubah:
- dari: `lookupColumn: "No WA"`, `lookupValue: user_phone`
- menjadi: `lookupColumn: "lid"`, `lookupValue: {{ $('Chat Counter').first().json.user_lid }}`

Sekarang `Read User STATS` selaras dengan `Cek_user_status` (yang memang mencocokkan by lid). User lama akan dikenali walau pesan masuk sebagai @lid → status tidak hilang → bot tidak tanya ortu/anak lagi.

## Validasi

## Catatan / belum dikerjakan (sesuai scope yang dipilih: fix minimal)
- **Baris duplikat lama** (mis. row 124 & 125 yang berbagi lid sama) masih ada di sheet. Belum dibersihkan. Bila dua baris berbagi lid dan salah satunya yang punya `user_status`, `Cek_user_status` mengambil baris pertama yang cocok — disarankan merge manual baris duplikat agar bersih.
