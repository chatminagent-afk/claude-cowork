## Perubahan V3.1

### 1. Disiplin segmentasi program (fix chat #1) — prompt + Preprocess
- **System prompt** `# REKOMENDASI PROGRAM`: tambah aturan SEGMENTASI — "sebut HANYA program yang cocok dengan kelas anak; JANGAN menyebut/menawarkan/membandingkan tier program lain (mis. Seniors/Mock saat membahas anak Junior/Intermediate) kecuali user bertanya langsung."
- **Preprocess** blok grade+program: tambah instruksi `Sebut HANYA program {X}, jangan tawarkan tier lain kecuali user tanya.`

### 2. Tidak re-greet returning user (fix chat #2, prompt-only) — prompt
- **System prompt** `# STATUS`: "Kalau status sudah ada (returning user) ATAU greeting sudah pernah dikirim → JANGAN ulang sapaan pembuka 'orang tua atau murid'. User balas singkat ('ok','makasih','🙏') tanpa pertanyaan baru → balas singkat & natural, jangan reset percakapan."
- Catatan: identitas parent/student memang sudah durable via tab STATS. **Sisa risiko yang DISADARI:** detail kelas/program anak TIDAK dipersist ke sheet (sesuai pilihan prompt-only), jadi setelah jeda sangat panjang + restart n8n, bot mungkin menanya ulang kelas. Kalau mau tutup penuh → opsi "tambah kolom STATS" (grade, recommended_program, gform_sent).

### 3. Out-of-scope + anti-loop + handoff (fix chat #3) — prompt + Preprocess
- **Preprocess** baru:
  - `6b` deteksi out-of-scope: `mahasiswa | semester N | (lagi/sudah/udah) kuliah | sarjana | magister | fresh graduate | gap year | karyawan | pegawai | sudah/udah lulus | sudah/udah kerja`. (Sengaja TIDAK memakai kata "kuliah" telanjang agar "anak mau kuliah di Singapura" tidak salah-flag.)
  - `6c` deteksi balasan ambigu super-pendek (`<=4 char`, mis. "inii") yang bukan greeting/grade/status/intent daftar.
  - aiContext: kalau out-of-scope → "sampaikan jujur belum ada program, JANGAN tanya kelas SMP/SMA"; nudge "tanya kelas" di-skip saat out-of-scope.
  - aiContext: kalau balasan ambigu → "JANGAN ulang pertanyaan yang sama; kalau sudah pernah tanya hal sama → tawarkan [TALK_TO_SAM]."
  - Flag `outOfScope`, `unclearReply` ditambah ke output node.
- **System prompt** `# ALUR`:
  - `2b` user di luar jenjang (mahasiswa/kuliah/kerja/dewasa) → jujur belum ada program, JANGAN tanya kelas, boleh tawarkan kalau ada adik SMP-SMA. Stop.
  - `2c` ANTI-LOOP: klarifikasi maksimal 1x; kalau masih tidak jelas → `[TALK_TO_SAM]`.

### 4. Fix tag bocor `[USERSTATUS:UNKNOWN]` (ketemu saat user uji V3) — Process All + prompt
Gejala: bot mengirim `[USERSTATUS:UNKNOWN] Halo! ...` (tag ikut terkirim).
Akar: stripper di node `Process All` terlalu ketat: `/\[USER_STATUS:(PARENT|STUDENT)\]/g` — tag yang dikirim model tanpa underscore (`USERSTATUS`) dan bernilai `UNKNOWN` tidak cocok → lolos. (Ada di V3 maupun V3.1 awal.)
Fix:
- **Process All** strip jadi toleran: `/\[\s*USER[_\s]?STATUS\s*:\s*[^\]]*\]/gi` → menangkap `[USERSTATUS:UNKNOWN]`, `[USER STATUS: ...]`, huruf besar/kecil, nilai apa pun. Regex deteksi status (untuk simpan ke DB) tetap hanya capture PARENT/STUDENT.
- **Prompt** `# STATUS`: nilai tag HANYA PARENT/STUDENT (tidak ada UNKNOWN/EMPTY); kalau status belum diketahui → JANGAN pasang tag status apa pun.
Diuji: 5 varian tag berhasil dibersihkan; syntax Process All OK.
