**Temuan tambahan:**
- **Cloudflare 1010:** request dengan User-Agent default `Python-urllib` diblok di edge (`HTTP 403`, body `error code: 1010`) **sebelum** sampai aplikasi. Setelah set User-Agent normal → tembus. **Node HTTP Request n8n mengirim UA sendiri**, jadi ini tidak memengaruhi produksi — tapi dicatat bila ada yang tes manual pakai curl/script.
- **Deteksi duplikat:** pesan identik yang diulang dalam window singkat → `HTTP 200 {success:true, data.duplicate:true, "Pesan sudah terkirim sebelumnya"}`. Relevan untuk retry/tes ulang; di produksi pesan umumnya berbeda.
- **Kirimi fetch media server-side.** `media_url` harus dari host yang mengizinkan unduh oleh server Kirimi (Wikimedia thumb menolak). Rencana brosur pakai Google Drive `uc?export=download&id=…` dengan "Anyone with link" **wajib diuji nyata** sebelum go-live.

## 4. Defect ditemukan & status fix

| ID | Defect | Severity | Status |
|----|--------|----------|--------|
| **D1** | Regex status LINKS `/aktif\|active\|on\|ya/i` melakukan **substring match** — `"NONAKTIF"` mengandung `"aktif"` & `"on"` sehingga baris NONAKTIF salah dianggap AKTIF. 2 lokasi di `codenodes.py`: blok LINK aktif untuk prompt (`FAQ_RETRIEVE`) & blok resolve media (`PROCESS_ALL`). | Tinggi (media salah kirim / prompt salah) | **FIXED** |

**Fix:** kedua regex diganti exact-word match `^\s*(aktif|active|on|ya)\s*$/i`. Diverifikasi:
- T5e membuktikan defect lama (match `NONAKTIF`) **dan** perilaku benar regex baru (tolak `NONAKTIF`/`DRAFT`, terima `Aktif`/`AKTIF `).
- Rebuild `assemble.py` dijalankan; pola baru muncul **2×** di `2026-07-16-VIRA-PCR-main.json`, pola lama **0**.

**Catatan (bukan defect kode, perlu perhatian saat wiring):**
- Media_url gagal → **HTTP 500 / success:false**. Node `Send Media Kirimi` memakai `onError:"continueErrorOutput"` → cabang error ke `Notify Admin Media Error` **akan** ter-trigger pada 500. Asumsi error-branch **benar**.
- Untuk teks, sukses selalu `HTTP 200 success:true`. Pastikan node `Check API Response` (setelah `Reply Chat Kirimi`) mengevaluasi field **`success`** pada body, bukan sekadar HTTP 200, sebagai jaga-jaga bila Kirimi mengembalikan 200+success:false pada kasus tertentu.

## 6. Risiko tersisa / belum bisa diuji tanpa n8n live

Unit test hanya mengeksekusi **logika code node** secara terisolasi. Yang **belum** terverifikasi (butuh import ke n8n + Sheets + Kirimi live):
1. **End-to-end webhook** Kirimi → trigger n8n (parsing payload `from`/lid, dedup webhook).
2. **Google Sheets I/O** — read CONFIG/STATS/MSG_BUFFER/PRODUK/LINGKUNGAN/FAQ/LINKS; append SURVEY/EVENTS/UNKNOWN; update STATS. Nama kolom & tipe harus cocok skema V4.
3. **Timing debounce** (baton `last_reply_ts`/`buffer_done_ts`/`debounce_ts`), race condition pesan beruntun, dan `Re-Read STATS Debounce`.
4. **AI Agent (Anthropic)** — apakah model benar-benar memancarkan tag (`[SEND_MEDIA]`, `[SCHEDULE_SURVEY]`, `[FACTS]`, dst.) sesuai prompt. Code node hanya mem-parse output; kualitas prompt & kepatuhan format tidak diuji di sini.
5. **Rate limit / whitelist** gating saat live.
6. **Wiring credential** (Google SA, Anthropic, Kirimi httpCustomAuth) — semua masih placeholder `REPLACE_*`; harus diisi saat import.
7. **Delivery media nyata** via Google Drive URL (lihat catatan fetch server-side Kirimi).
